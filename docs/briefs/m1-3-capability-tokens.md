# Brief: 중립 능력 토큰과 하네스 능력 표

- SSOT: §3, §6 C1
- 작업 항목: M1-3
- 날짜: 2026-11-06

## 무엇을, 왜

정본이 하네스 능력을 가리키는 표기를 정하고([ADR-0003](../adr/0003-neutral-capability-tokens.md)), 네 하네스의 능력 표를 M0 실측값으로 채운다. 이 표가 M1-6 build의 입력이다. 표에 빈칸이 있으면 배포본에 토큰이 남거나(C1 위반) 없는 도구를 호출하게 된다.

## Acceptance

| # | 기대 결과 | 금지 결과 | 증거 |
|---|---|---|---|
| A1 | 네 하네스 표가 21개 능력을 빠짐없이, 더도 덜도 없이 정의한다 | 한 하네스에서만 빠진 능력 | 🔒 unit |
| A2 | 모든 렌더링이 비어 있지 않고, `native` 여부를 밝히며, 토큰을 포함하지 않는다 | 대체 경로가 "skip"으로 남음 | 🔒 unit |
| A3 | `sync/substitutions.json`이 만드는 토큰은 모두 능력 목록에 있다 | 렌더링할 수 없는 토큰 생성 | 🔒 unit |
| A4 | 표마다 실측 하네스 버전과 날짜가 있다 | 근거 없는 렌더링 | 🔒 unit |
| A5 | 표기법, 하네스별 렌더링, 모델 시트 위치를 ADR로 남긴다 | 결정이 계획 문서에만 남음 | 📎 ADR-0003 |

## 범위 밖

- 렌더링을 실제 본문에 적용하는 build(M1-6).
- 어색한 문장 고치기(M2-2).

## 남은 위험

- 렌더링 문구가 실제 문장에 자연스럽게 들어가는지는 build 결과를 봐야 안다. M2-2에서 문장 단위 fork로 처리하고, 20곳을 넘으면 ADR-0003을 다시 본다.
