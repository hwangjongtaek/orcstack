# Brief: 게이트 뒤 playbook 건너뛰기 보강

- SSOT: §4 F1, §6 C5
- 작업 항목: M5-5
- 날짜: 2026-11-06

## 무엇을, 왜

M5-3 라우팅 스모크에서, 기능·리팩터링 요청이 `orc-mode`를 부르고 게이트까지 간 뒤 playbook 파일을 열지 않고 바로 작업했다(기능 0/3, 리팩터링 CI 1회 실패). playbook은 작업 순서(acceptance 먼저, fence 먼저)를 정하는 곳이라, 건너뛰면 orcstack이 하는 일이 사라진다.

원인은 `orc-mode` 본문에 있었다.

- 게이트 마지막 줄이 SSOT 없는 저장소에 대해 "Do the task"라고 말한다. 이 말이 남은 절차를 건너뛰라는 뜻으로 읽힌다.
- playbook 지시(`## Playbooks`)는 본문 끝 가까이에 떨어져 있다.

고친 내용:

- 그 줄을 "2·3단계만 건너뛰고, 나머지는 그대로 적용한다"로 바꿨다.
- 게이트 바로 뒤에 다음 규칙을 넣었다. 코드나 문서를 바꾸는 작업은 저장소가 governed든 아니든, Project extensions → playbook 선택 → playbook 파일 열기 → {{todo}}에 단계 복사를 마친 뒤에 일을 시작한다.
- 테스트, fence, 스크립트, 수정을 그 전에 쓰면 playbook을 건너뛴 것이다.

## 측정 (2026-11-06, Claude Code 2.1.319, sonnet, 구독 토큰)

같은 요청을 수정 전 dist 사본과 수정 후 dist로 반복 실행했다.

| 경우 | 수정 전 | 수정 후 |
|---|---|---|
| 기능 | 0/3 | 4/5 |
| 리팩터링 | 2/3 | 5/5 |
| 버그 | (M5-3 2/2) | 2/2 |
| 질문 | (M5-3 2/2) | 2/2 |
| 끄기 | (M5-3 2/2) | 2/2 |

- 수정 후 기능 실패 1회: 게이트 뒤 파일을 읽고 끝났다. 아무것도 쓰지 않았으므로 "playbook 없이 구현"은 아니다.
- 스모크 저장소에 화면 코드가 없어 버튼 위치를 되물었을 가능성이 있다. 당시 스크립트는 최종 답변을 저장하지 않아 확인하지 못했다. 이제 보고에 답변 앞부분(`reply`)을 담는다.
- 비용: 구독 사용량, API 환산 약 $4.2.

## 범위 밖

- SSOT가 있는 저장소에서 기능 요청이 SSOT 승인을 먼저 묻는지 확인하는 경우. 라우팅 스모크에 governed fixture를 더하는 일은 따로 한다.
- sonnet 외 모델과 다른 하네스의 라우팅.
