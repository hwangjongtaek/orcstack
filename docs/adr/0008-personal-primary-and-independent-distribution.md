# ADR-0008: 개인 프로젝트 정본과 독립된 회사 배포본

- 상태: Accepted
- 날짜: 2026-11-15
- 마일스톤: Bootstrap

## 맥락

저장소 소유자는 개인 프로젝트에 orcstack, Datamaker 프로젝트에 dstack을 사용한다. orcstack을 주 개발 저장소로 유지하되 dstack에는 orcstack 연결이나 언급을 넣지 않도록 요청했다. 두 플러그인이 같은 환경에 설치될 수 있다.

## 결정

orcstack 0.1.1은 dstack 커밋 `8f580981babecb6cc194406c414e0e8a0751b264`에서 시작한다. `orc-mode`, `orc-help`, `orc-agent`, `adopt-orcstack`, `setup-orcstack` 이름으로 진입점을 분리한다. 공통 skill은 같은 설치본의 절대 경로로 읽는다. 제공된 PNG 원본을 마스코트로 사용한다.

선택은 `WORKFLOW_STACK`, 프로젝트 `.workflow-stack.json`, 단일 프로젝트 설정 순으로 결정한다. 공존 상태에서 선택이 없으면 질문한다. 기존 dstack 훅의 중복 활성화를 막으려면 세션 실행기가 미선택 훅을 시작 전에 끈다.

업데이트는 orcstack 쪽의 도구가 변경된 공유 코드만 dstack 이름으로 변환해 별도 디렉터리에 내보낸다. 회사 저장소는 자동 수정하지 않는다. 회사 기록과 자산은 전달 범위에서 제외한다. 원본 저작권 고지는 보존한다.

## 버린 대안

회사 저장소에 remote나 자동 수신 workflow를 추가하면 독립 배포 조건을 위반한다. 전체 스냅샷을 덮어쓰면 회사의 별도 수정을 잃는다. 세션마다 환경 변수 없이 선택 문구만 주입하는 방법은 기존 dstack 훅을 비활성화하지 못한다.

두 설계 후보를 비교한 뒤 프로젝트 선택과 해시 기반 변경 묶음을 기본으로 정했다. 두 번째 후보의 세션 실행기를 결합했다. 별도 계열 cross-judge는 실행하지 않았으며 최종 변경은 독립 검토한다.

## 결과

`tests/selection.test.mjs`가 공존과 선택을 검사한다. `tests/export-downstream.test.mjs`가 대상 보존, 충돌, 참조 유출과 적용 확인을 검사한다. 공유 변경 적용과 회사 CI 검증은 리뷰어가 수행한다.

## 재검토 조건

dstack이 중립적인 선택 규약을 지원하거나 두 배포본의 공유 범위를 변경할 때 다시 검토한다.
